API для перевалов ФСТР
Небольшой REST API для отправки и просмотра данных о горных перевалах. Проект сделан на FastAPI, а данные хранятся в PostgreSQL.

Сейчас API умеет принимать новые записи, возвращать перевал по его ID, редактировать запись со статусом new и показывать все перевалы, отправленные пользователем.

Что нужно для запуска
Python 3.10 или новее
PostgreSQL
Установка
Склонируй репозиторий и перейди в папку проекта:

git clone https://github.com/Joilcrow07061998/pereval_project.git
cd pereval_project
Создай виртуальное окружение и активируй его. На macOS или Linux команды будут такими:

python3 -m venv .venv
source .venv/bin/activate
Установи зависимости:

pip install -r requirements.txt
Создай в PostgreSQL базу данных. По умолчанию проект ожидает базу с именем pereval.

Скопируй пример настроек:

cp .env.example .env
Затем открой .env и укажи свои данные для подключения к PostgreSQL. Пароль из своего локального файла никому не отправляй и не добавляй сам файл .env в Git.

Переменная	Для чего нужна
FSTR_DB_HOST	Адрес сервера PostgreSQL
FSTR_DB_PORT	Порт PostgreSQL
FSTR_LOGIN	Пользователь базы данных
FSTR_PASS	Пароль пользователя базы данных
FSTR_DB_NAME	Название базы; по умолчанию pereval
Запусти приложение из корневой папки проекта:

uvicorn app.main:app --reload
При запуске приложение создаёт таблицы, если их ещё нет. После запуска можно открыть Swagger UI и отправлять запросы прямо из браузера. OpenAPI-схема доступна по адресу /openapi.json.

Методы API
1. Отправить новый перевал
POST /submitData

Пример тела запроса:

{
  "beauty_title": "пер.",
  "title": "Тестовый перевал",
  "other_titles": "Верхний перевал",
  "connect": "",
  "add_time": "2026-10-28T12:00:00",
  "user": {
    "email": "tourist@example.com",
    "fam": "Иванов",
    "name": "Иван",
    "otc": "Иванович",
    "phone": "+79990000000"
  },
  "coords": {
    "latitude": 45.123,
    "longitude": 7.456,
    "height": 1500
  },
  "level": {
    "winter": "1А",
    "summer": "1Б",
    "autumn": "1А",
    "spring": "1Б"
  },
  "images": [
    {
      "data": "https://example.com/pass.jpg",
      "title": "Вид на перевал"
    }
  ]
}
При успешном сохранении вернётся ID созданной записи:

{
  "status": 200,
  "message": null,
  "id": 1
}
Новая запись получает статус new. Если не заполнены обязательные поля, API вернёт HTTP 400 и перечислит, чего не хватает. При ошибке базы данных вернётся HTTP 500.

2. Получить перевал по ID
GET /submitData/{id}

Например:

GET /submitData/1
В ответе будут данные перевала, его ID и статус модерации, информация об авторе, координаты, уровни сложности и фотографии.

Если перевал с таким ID не найден, API вернёт HTTP 404.

3. Отредактировать перевал
PATCH /submitData/{id}

Метод принимает JSON с теми же полями, что и POST /submitData. Передавай полные данные перевала, который нужно обновить.

Редактировать можно только запись со статусом new. Поля пользователя — ФИО, email и телефон — при обновлении не меняются. Если запись уже имеет другой статус или не найдена, обновление не выполняется.

Успешный ответ:

{
  "state": 1,
  "message": "Данные перевала успешно обновлены"
}
Если обновить запись не удалось, state будет равен 0, а в message будет указана причина.

4. Получить все перевалы пользователя
GET /submitData?user__email=<email>

Например:

GET /submitData?user__email=tourist@example.com
API вернёт список перевалов, отправленных пользователем с указанной почтой. У каждой записи есть собственный статус модерации. Если у пользователя пока нет перевалов, вернётся пустой список.

Как устроена база данных
Данные разделены на связанные таблицы:

users — информация о пользователях;
mountain_passes — основные данные о перевалах и их статусах;
pass_coordinates — координаты;
pass_levels — уровни сложности по сезонам;
pass_images — фотографии перевала.
Так данные пользователя не дублируются при отправке нескольких перевалов с одной и той же почты.

Важно
Это учебный проект. Перед использованием в реальном сервисе нужно отдельно настроить безопасное развёртывание, управление доступом, миграции базы данных и мониторинг.
